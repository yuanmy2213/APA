## 1 原型、实现与入口

- [在线交互预览](https://finance-access-review-20261016.garden-rook-7646.chatgpt.site/)
- [原型源码与运行方法](../prototype/README.md)
- 正式运行界面：`frontend/`，由 Java 服务同源提供，数据写入服务端数据库。

`prototype/` 为独立静态原型，使用虚构数据和浏览器本地状态，不连接 Java 数据库，不提供真实登录权限隔离。它用于页面和交互评审，不用于上传真实财经权限数据。正式运行版的导入、异步任务、发布、版本和授权边界，以一期详细设计为准。

## 2 信息架构与主要操作

| 页面/区域 | 核心信息 | 关键操作与去向 |
| --- | --- | --- |
| 首页总览 | 授权、风险、用户及产品分布；数据覆盖与时间 | 点击产品或风险数量，进入该产品汇总或风险明细 |
| 产品审查汇总 | 检查项、内容、结果、风险数、等级 | 点击明细进入对应用户角色/权限矩阵栏目 |
| 风险明细 | 用户—角色、权限矩阵两个栏目；按字段筛选 | 筛选、列显示、分页、导出、点击记录下钻 |
| 原始记录抽屉 | 本轮风险、依据、建议、原始字段 | 查看来源，填写修改原因后保存，进入待复核 |
| 数据管理 | 产品范围、导入类别、模板、数据版本 | 下载模板、选择文件、查看校验、确认替换；正式版另含草稿与发布流程 |
| 规则说明 | 用户权限规则和矩阵细则、判定依据 | 查看规则适用范围、初筛和人工确认说明 |

正式运行版另设独立原始记录页面，支持没有风险的原始授权/权限点记录查询与修订。原型页面不应代替这类服务端能力的验证。

## 3 页面与视觉约定

采用浅色背景、白色信息卡、深色文字、蓝色主操作；风险使用高/中/低标签并配合文字，不能只依赖颜色区分。总览优先呈现管理者判断所需的数量和产品比较，操作页面以表格和来源记录为主。列较多时横向滚动，保持字段筛选和下钻入口明确。

保持如下文案原样：

- （删除英文副标题）
- `财经权限，全量审查`
- `8项检查 · 第8项含6条矩阵细则`

标题描述业务目标，不代表一期自动执行了全部审查。检查目录与当前编码见总体架构与一期详细设计。

## 4 交互与状态约定

| 场景 | 展示与操作要求 |
| --- | --- |
| 数量可下钻 | 使用链接/按钮样式并保留产品、栏目和筛选上下文 |
| 数据未提供或部分覆盖 | 显示覆盖说明，不把未知显示为通过或真实零值 |
| 风险为零 | 不自动将未执行检查标记为通过 |
| 筛选后无记录 | 展示空状态与清除筛选入口 |
| 导入校验失败 | 显示错误，保留当前有效数据；正式版由服务端校验 |
| 全量替换 | 明确目标产品、数据类型和覆盖范围；正式版发布前不影响领导看板 |
| 编辑原始数据 | 必填原因，保留本轮风险，进入待复核，不等同于生产 iAuth 整改 |
| 关闭抽屉/弹窗 | 提供明确关闭与取消入口，避免误操作 |

## 5 复现与验证边界

原型业务源码直接取自已发布预览的 dist 目录；第三方依赖通过固定版本恢复，并校验 SHA-256。Vue 文件复用正式前端随仓库提供的相同版本，SheetJS 从锁文件指定依赖恢复。界面和数据逻辑不因打包目录变化而改写。

本次补充提交执行语法检查、依赖一致性、静态资源引用和 DOM 挂载检查。真实浏览器的布局、移动端视觉、键盘与读屏完整体验仍需浏览器验收；DOM 检查不能代替这些验证。
