| 变更 | 结果与兼容 |
| --- | --- |
| 路径前缀 | CONTEXT_PATH支持/apa，前端API改为相对路径；Java默认根路径，部署包默认/apa |

| 历史兼容 | 旧权限点获得LEGACY-标识，确定关联的风险回填；风险原因、判定依据、旧版本与原文件保留 |

| 数据接口 | /api/integration/v1支持JSON/文件上传、任务与错误、查询、草稿定位、PATCH及可配置的显式发布 |

## 升级

1. 备份数据库及audit.storage文件目录，保留原环境配置。
2. 构建mvn package，产物target/finance-access-review-1.3.0.jar。执行python3 scripts/package-release.py可生成独立部署目录；复制至部署位置再运行，不将持久数据放在会被构建清理的target中。
3. 启动自动执行Flyway V3。V1/V2脚本原校验和不变，无需删除数据库或重新上传历史数据。
4. 之后改用真实组合ID重新导入时，同步提供矩阵风险的新外键；否则旧LEGACY-ID风险会明确显示未关联，不按名称猜测。
5. Java根路径默认不变；包内bin/start.sh默认/apa，CONTEXT_PATH=/表示根路径。原有JAVA_OPTS继续生效，context-path由独立参数传入。
6. 接口按需设置INTEGRATION_TOKEN和INTEGRATION_PRODUCTS；默认不允许接口发布，需AA/质量运营审核。按流程可显式配置INTEGRATION_CAN_PUBLISH=true。

用户此前在package目录手工追加的启动参数已归入deploy/bin/start.sh模板，打包时自动带入，无需再次编辑未跟踪脚本。源码仓库不包含真实密钥、体验数据库、target构建产物或原始企业权限报告。

实际验证及性能证据以本轮验证记录为准。PostgreSQL、企业认证、真实业务报告与目标浏览器仍按既有目标环境验收边界执行。
