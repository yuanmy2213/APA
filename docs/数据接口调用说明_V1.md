# 财经权限审查数据接口 V1

对应运行版本V1.3.0，2026-10-20。接口定义见[OpenAPI](openapi-integration-v1.yaml)，可执行示例见[scripts/integration-client.py](../scripts/integration-client.py)，四类完整JSON示例见[双业务ID数据](../examples/接口上传_双业务ID.json)。所有示例均为虚构数据。

## 1 地址、身份与权限

接口地址为`{应用地址}/api/integration/v1`。根路径部署示例为`http://127.0.0.1:8080/api/integration/v1`；`CONTEXT_PATH=/apa`时为`http://127.0.0.1:8080/apa/api/integration/v1`。客户端的`--base-url`填写应用地址，末尾不要再拼`/api`。

| 服务端环境变量 | 默认与用途 |
| --- | --- |
| CONTEXT_PATH | Java应用默认空，兼容根路径；发布包bin/start.sh默认`/apa`，设为`/`可使用根路径 |
| INTEGRATION_TOKEN | 默认空，接口关闭；启用时至少32字符，由部署环境注入 |
| INTEGRATION_PRODUCTS | 默认空，无产品范围；例如`P06,P07`；显式`*`表示全部产品 |
| INTEGRATION_CAN_PUBLISH | 默认false；允许上传与修订草稿，AA/质量运营审核发布；true时允许接口显式发布 |

请求携带`Authorization: Bearer <接口密钥>`。该身份固定记为`integration`，与页面Basic登录独立；网页端仍验证CSRF，不能把网页账号密码直接用于这组接口。Bearer接口不依赖Cookie或CSRF令牌。生产环境通过现有HTTPS入口调用，密钥由环境配置管理。

客户端从`APA_API_TOKEN`读取密钥；不要把真实密钥写入代码、JSON数据或命令行参数。上传和修改均沿用原文件、草稿、快照、审计与发布机制。

## 2 数据标识与关联

| 对象 | 字段 | 约束 |
| --- | --- | --- |
| 原始权限点POINT | permissionCombinationId／权限组合ID | 字符串，最多200字符；同一产品的数据版本内唯一。不同组合ID可以引用相同权限点ID |
| 权限矩阵风险MATRIX_RISK | permissionCombinationId | 作为业务外键，按该ID关联当前原始权限点版本；ruleCode为8a—8f |
| 原始授权AUTH | authorizationId／授权记录ID | 有ID时保持原有来源、应用、租户范围的判重；无ID仍逐行完整保留 |
| 用户角色风险USER_RISK | authorizationId | JSON接口必须提供，按授权记录ID关联；同一ID跨应用存在多候选时需补充来源范围 |

所有标识按字符串传递，保留前导0及大小写；不要传JSON数字。权限组合ID和已存在的授权记录ID不通过PATCH修改，身份变化使用重新导入。修改权限名称、有效期、角色分类等普通字段仍支持。旧授权补齐缺失ID时，只同步已关联风险中原先为空的外键，历史审查来源保持原样。

新JSON中的POINT和MATRIX_RISK必须提供权限组合ID。历史Excel/CSV缺少该字段时继续兼容：原始权限点生成`LEGACY-`前缀ID，唯一匹配的历史风险回填该ID；不确定时保留未关联/多候选诊断。V3迁移也为历史数据库补齐这些标识。

风险记录可以先于原始数据上传，因此关联是受版本与产品范围约束的业务外键，不把孤立风险伪造为已关联。显式ID不存在时不会退化为名称匹配。原始数据仍缺失时，风险记录保留，统计覆盖状态不被虚构为完整。

## 3 上传

| 方法与路径 | 内容与结果 |
| --- | --- |
| POST /products/{product}/imports | JSON上传；返回202及导入任务 |
| POST /products/{product}/files | multipart文件上传；参数与页面导入一致 |
| GET /import-jobs/{id} | 查看QUEUED/RUNNING/VALIDATED/FAILED、真实行/Sheet进度、错误预览、draftId |
| GET /import-jobs/{id}/errors/page?page=1&pageSize=100 | 分页读取全量错误；每页最多200条 |
| GET /templates/{kind} | 下载user/matrix/all模板，包含新的业务ID列 |

两类上传都须携带8—100字符的`Idempotency-Key`。同一身份、产品及幂等键重复相同内容返回原任务；内容改变返回409。JSON对象字段顺序不影响幂等识别，数组顺序属于上传内容。

JSON格式：

```json
{
  "schemaVersion": "1",
  "mode": "auto",
  "rawCoverage": "FULL",
  "riskCoverage": "FULL",
  "sourceAsOf": "2026-10-20T10:00:00+08:00",
  "datasets": [
    {"type": "POINT", "rows": [{"permissionCombinationId": "C0001", "roleName": "角色", "setName": "权限集", "pointId": "00042"}]},
    {"type": "MATRIX_RISK", "rows": [{"permissionCombinationId": "C0001", "ruleCode": "8a", "risk": "高", "violation": "来源风险说明原值"}]}
  ]
}
```

datasets每次提供1—4种类型，同一类型不能重复。未提供的链路/数据对象继续使用基线；显式空rows表示空清单，完整空风险清单发布时仍须allowEmpty确认。mode为auto/user/matrix；覆盖范围为FULL/PARTIAL/UNKNOWN；sourceAsOf必须带时区。每类原始数据最多100,000条、风险最多20,000条；文件/JSON最多50MB，multipart总请求最多51MB。不截断后发布。

JSON记录字段使用OpenAPI中的英文属性名，未知字段、标识数字化、无效日期、重复业务ID等进入完整错误报告。只填写风险的业务外键和检查信息时，可从确定关联的原始记录补齐空白展示字段；已有风险原因、判定依据及非空来源值不被覆盖。

```bash
python scripts/integration-client.py --base-url http://127.0.0.1:8080/apa --product P06 upload-json examples/接口上传_双业务ID.json --wait
python scripts/integration-client.py --base-url http://127.0.0.1:8080/apa --product P06 upload-file report.xlsx --source-as-of 2026-10-20T10:00:00+08:00 --raw-coverage FULL --wait
```

202只代表任务受理；必须轮询到VALIDATED，随后审核发布。校验失败不会影响当前看板。

## 4 查询和修改

先`POST /snapshots`取得快照。`POST /source-records/query`和`POST /findings/query`复用页面查询契约：snapshotId、productId、kind、page、pageSize、q、filters。新字段支持等值/包含筛选、排序与导出。

```json
{"snapshotId":"返回的快照ID","productId":"P06","kind":"matrix","page":1,"pageSize":20,"filters":[{"field":"permissionCombinationId","op":"eq","value":"C0001"}]}
```

修改流程：

1. `POST /products/{product}/drafts`，body为`{"kind":"matrix"}`、user或both。
2. `POST /drafts/{id}/records/resolve`，按业务ID在草稿版本定位。原始记录传`{"kind":"matrix","source":true,"businessId":"C0001"}`；风险传source=false并提供ruleCode。授权ID跨应用有多条时增加appId、tenantId或sourceSystem，不任取第一条。
3. 使用返回source.id或finding.id调用对应PATCH，携带其recordVersion作为If-Match。
4. `GET /drafts/{id}`核对数量、关联诊断、版本差异及revision后发布。

没有业务ID的历史授权可通过`GET /drafts/{id}/record?originalId=原始UUID&kind=user&source=true`定位草稿副本；originalId来自已授权快照的查询结果。

| 方法与路径 | 请求要点 |
| --- | --- |
| PATCH /drafts/{id}/source-records/{row}?kind=matrix | If-Match：记录版本；body：changes与必填reason |
| PATCH /drafts/{id}/findings/{row} | 允许risk/workflow/violation/advice/evidence/confidence；不允许通过报告纠错改业务外键 |
| POST /drafts/{id}/publish | If-Match：草稿revision；Idempotency-Key；body包含reason及allowEmpty |

```json
{"changes":{"pointName":"核实后的权限点名称"},"reason":"依据原始权限矩阵核实"}
```

```bash
python scripts/integration-client.py --base-url http://127.0.0.1:8080/apa --product P06 patch-source --kind matrix --business-id COMBO-000001 --changes '{"pointName":"核实后的名称"}' --reason 核对来源记录
python scripts/integration-client.py --base-url http://127.0.0.1:8080/apa --product P06 patch-risk --kind matrix --business-id COMBO-000001 --rule-code 8a --changes '{"workflow":"已确认误报"}' --reason 已完成核实
```

可用`--changes-file changes.json`代替命令行JSON，避免Windows等环境的引号转义问题。需要继续修改同一草稿时传`--draft`，避免创建多份并行草稿。

PATCH返回新的recordVersion和draftRevision。它只保存草稿；发布后看板生效，原始副本修改使关联风险进入待复核。确认误报发布后剔除统计，原始风险记录与旧快照仍保留。接口身份默认不允许发布；按流程配置允许后，可显式执行：

```bash
python scripts/integration-client.py --base-url http://127.0.0.1:8080/apa publish --draft 返回的草稿ID --reason 审核后发布
```

## 5 错误与重试

| 状态 | 常见code与处理 |
| --- | --- |
| 401 | INTEGRATION_AUTH_REQUIRED：未配置、缺失或无效接口密钥 |
| 403 | FORBIDDEN：缺发布权限；SCOPE_CHANGED：快照范围不属于当前身份 |
| 404 | NOT_FOUND：越权产品/任务/记录，或定位不到业务ID |
| 409 | IDEMPOTENCY_CONFLICT、AMBIGUOUS_BUSINESS_ID、BUSINESS_ID_IMMUTABLE、DRAFT_STATE |
| 412 | RECORD_CHANGED、DRAFT_CHANGED、BASE_CHANGED：重新读取/核对，不直接覆盖重试 |
| 413 | FILE_SIZE：文件或请求超限 |
| 422 | 参数、字段、时间、覆盖范围、链路或JSON结构无效 |
| 428 | VERSION_REQUIRED：缺少If-Match |

上传网络超时用同一个幂等键重试；新内容使用新键。记录修改遇到412先重新定位并核对版本。数据库与文件存储沿用现有备份规则；接口不会直接修改生产iAuth。
