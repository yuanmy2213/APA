# V1.4.0 产品名称与首次上线数据契约

日期：2026-10-20。前一版本V1.3.0，代码与设计继续使用同一仓库及原架构文档路径。

## 本次变化

修复部分Excel文本类型漏读，同时继续拒绝实际公式。四类标准模板首列增加必填“产品名称”，提供18产品下拉选择，导入时逐行与页面/接口所选产品校验。一次上传一个产品，填错、漏填或混合产品均报具体工作表及行号，整包失败，已发布数据不受影响。导出明细和完整JSON示例同步包含产品名称。

权限组合ID在原始权限点与矩阵风险中必填，用户角色风险必须提供授权记录ID；风险仅按这些ID关联同产品版本的来源。取消LEGACY-ID生成、按名称降级、旧10a—10f自动转换与历史库回填。保留实用字段别名，以及用户明确要求的无授权ID原始行完整导入；这些行不会按用户/角色名称自动关联风险。

数据库初始化合并为V1__core.sql，含诊断、进度和性能索引；删除V2/V3历史迁移及相关升级测试，新增空库约束验证。草稿、发布、快照、原文件、审计与回退继续用于今后的持续审查，原始副本编辑不操作生产权限。风险原因、判定依据原值不改写，确认误报发布后剔除统计。

保留相对API路径、CONTEXT_PATH、/apa启动模板、受控数据接口，以及上版批量复制/暂存、独立编辑组件、局部保存和防抖取消查询。已审核环形图、22px侧栏与页面布局保持。

## 部署与重建

系统尚未上线，本版按新建库部署，不升级旧开发库，也不会在启动时自动清库。

使用默认H2体验环境时：

1. 停止原应用，关闭占用数据库的Java进程。
2. 使用新的部署目录，或将原部署目录的data文件夹改名为data-pre-v1.4。
3. 启动本版程序，自动建立空库和18产品字典。
4. 下载本版模板重新填报；也可选择“财经法务产品”上传examples中的新版虚构演示工作簿。

PowerShell示例（在已停止应用的部署目录执行）：

```powershell
Rename-Item -Path .\data -NewName data-pre-v1.4
.\start-demo.bat
```

若目标备份文件夹已存在，改用不同名称或独立部署目录。自定义DB_URL时将其指向新的空数据库，FILE_STORAGE指向新的文件目录。不要通过Flyway repair跳过旧库校验。重建后本版本的正常重启保留数据，已用真实HTTP文件库重启验证。

构建`mvn package`后执行`python3 scripts/package-release.py`生成target/package/finance-access-review；bin/start.sh默认/apa，CONTEXT_PATH=/表示根路径。生产profile需配置数据库、账号与文件存储；体验可设置SPRING_PROFILES_ACTIVE=demo。

## 接口变化

路径仍为/api/integration/v1，JSON schemaVersion仍为1（首次上线契约）。四类rows每行新增必填productName，例如“财经法务产品”，必须与/products/P06一致；缺失或不匹配进入全量校验错误。Excel、XLS、CSV、JSON使用相同业务校验。未提供的对象保留基线，显式空清单继续要求确认。

[调用说明](数据接口调用说明_V1.md)、[OpenAPI](openapi-integration-v1.yaml)、[客户端](../scripts/integration-client.py)与[JSON示例](../examples/接口上传_双业务ID.json)同步更新。接口密钥、产品范围、幂等、If-Match与显式发布要求保留。
